Clinical TinyGPT: a language model built from scratch

Large language models like ChatGPT can feel like magic. This project takes the magic apart. I built a small GPT-style model piece by piece, trained it on clinical text on a laptop GPU, and measured what every piece does. This guide walks you through it in six short chapters. You don't need any machine learning background.

Data: about 30,000 de-identified clinical case notes (augmented-clinical-notes, MIT license) plus public PubMed abstracts. The model is a learning project and is not for clinical use.

Preview: these charts come from a short CPU test run with tiny models. They show the real pipeline, but the numbers will change when the full runs on the laptop GPU finish.

1. Tokenization: turning text into numbers

A model can only do math on numbers, so the first step is to cut text into pieces called and give each one an ID. My tokenizer uses . It starts from single bytes, then repeatedly glues together the pair of pieces that appears most often in the training text. After thousands of merges, common clinical words like "patient" become a single token.

What this means

Fewer tokens per word means shorter sequences, so the model can read more text in its fixed window and trains faster. GPT-2's tokenizer was built on web text, which is why it splits medical words into more pieces than a tokenizer trained on clinical notes.

3. Training: learning to guess the next token

Training shows the model a window of real text and asks it to predict each next token. The measures how surprised it was. After each batch, the nudges millions of weights to make it a bit less surprised next time. Click a model in the legend to show or hide it.

What this means

All the curves drop quickly at first, as the model learns spelling and common words, then flatten out. Bigger models end lower. Validation loss comes from notes the model never trained on, so it tracks training loss closely when the model is learning patterns instead of memorizing.

What this means

Loss falls steadily as the model grows, but each step up helps a little less. The floor the curve flattens toward depends on the data and the training budget, and adding parameters alone can't get below it.

5. The KV cache: writing fast

The model writes one token at a time. Each new token has to look back at every earlier one through attention, using a for each. Without a cache, the model recomputes all of them at every step. With a cache, it saves them and only computes the newest one.

Without cache
0 computed
With cache
0 computed
What this means

Without the cache, the work grows with the square of the text length. With it, the work grows linearly. That's why every production LLM uses one. The cost is memory for the saved keys and values.

How it's built

  • The tokenizer, attention, RoPE, RMSNorm, SwiGLU, KV cache and training loop are all written by hand in PyTorch. No model code is imported.
  • Every run is tracked in MLflow, every experiment has a YAML config and a make target, and training resumes from a checkpoint if the laptop shuts down.
  • All of it trains on a 6 GB RTX 4050 laptop GPU. The charts on this page are generated from the MLflow runs by one export script.
